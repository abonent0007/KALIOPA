# ChatGPT через Opera VPN: что измерено и как починено (2026-11-01)

## Итог

`chatgpt.com` открывается в обычном Chrome через системный PAC Nova:
`ai_apps → opera → 127.0.0.1:1371`, выход Opera (SE). Проверено headed Chrome:
заголовок «ChatGPT: Chat, Work, Create & Code with AI», русская страница входа.

## Почему раньше не работало

| Выход | chatgpt.com | Причина |
|---|---|---|
| direct (RU) | 403 | страна не поддерживается + ТСПУ |
| Cloudflare WARP 1370 | 403 | IP-диапазоны WARP в чёрном списке OpenAI |
| Tor 1375/1378 | 403 | публичные exit-узлы заблокированы |
| Opera 1371 (`.247.19`) | **200 в браузере** | чистый прокси-ASN Opera, JS-челлендж проходит headed Chrome |

`curl`/headless получают на всех выходах страницу «Enable JavaScript and cookies
to continue» — это Cloudflare-челлендж, а не геоблок. Поэтому проверять ChatGPT
нужно только реальным браузером.

## Почему Opera не запускалась

1. `relay.nova-app.eu:8443/2053` не отвечает (TCP timeout) — два relay-кандидата
   съедали по 6.5 с до direct discover.
2. Опубликованная лента (`opera_endpoints.json`) содержала только мёртвые
   endpoint'ы: `.80 .28 .42 .79 .26` (EU) и все AM/US — TCP открыт, туннель молчит.
3. Discover отдаёт `[.244.47, .247.19]`; `.244.47` мёртв, а режим `first` мог
   выбрать именно его и оставить процесс на 1371 навсегда.
4. `fastest` отключался после первого кода 12 и больше не использовался.

## Что изменено (1.44.2.11–1.44.2.12)

- TCP-гейт bootstrap-прокси: мёртвый relay пропускается за 1.2 с
  (`OperaProxyManager._bootstrap_proxy_reachable`).
- Discover идёт раньше опубликованной ленты; лента — запас.
- `-server-selection fastest` используется всегда, кроме явного override;
  замер выбирает `.247.19` за ~1 с.
- Опубликованный endpoint, не поднявший туннель, снимается, и берётся следующий
  (раньше мёртвый процесс оставался на 1371).
- Успешный endpoint кэшируется (`temp/opera_endpoint.json`); повторный старт
  поднимается за ~1 с.
- MTProto больше не идёт через `opera-http`: Opera не пропускает произвольный TCP
  (CONNECT к DC Telegram висит, порт 25 — 502). В попытках relay появился
  `egress: opera|tor|profile`; HTTP разрешён только для `profile` (xray).

## Если Opera снова умрёт

Приложение само: пропустит мёртвый кэш, вызовет discover, выберет быстрейший
endpoint и после серии неудач уйдёт в backoff `60·2^n` (до 30 мин). При этом
Telegram остаётся на WARP, ChatGPT — единственная группа, которой нужен Opera.
