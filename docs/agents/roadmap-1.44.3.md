# План 1.44.3: все незакрытые пункты, исследование → реализация → проверка

Каждый пункт проходит три шага: **investigate** (собрать факты, замерить), **implement**
(минимальная правка с тестом), **verify** (живая проверка на этой машине). Сборка — одна,
после прохождения всех фаз, версия `1.44.3.0`.

## Фаза A. Релей Telegram (самый шумный участок)

### A1. Запрет MTProto через Tor-HTTP
- investigate: в логе 49 × `502 Bad Gateway (tor protocol violation)`; подтверждено, что
  `route=opera-http` указывает на Tor (1378).
- implement: при выборе маршрута релея исключать Tor-HTTP для MTProto; порядок
  `warp-socks → direct → Opera-HTTP`.
- verify: 0 строк `502` за 10 минут работы Telegram.

### A2. `InvalidStateError` в proactor-loop
- investigate: 2 записи `invalid state` при смене маршрута; цикл «пропущен», туннели целы.
- implement: переключение маршрута — через закрытие старого цикла, не переиспользование.
- verify: смена маршрута 5 раз подряд, в логе нет `InvalidStateError`.

### A3. Выбор маршрута по скорости + даунгрейд логов
- investigate: сейчас маршрут задаётся настройкой, скорость 0.3–1.7 КБ/с через Tor.
- implement: per-route throughput RTT-статистика, выбор быстрейшего; `traffic path` раз в минуту,
  `probe diag` не чаще раза в 30 с.
- verify: размер лога за 10 минут падает в разы, скорость не хуже прежней.

## Фаза B. Узлы

### B1. Proton-варианты в обновление профилей
- investigate: `nova_proton_variants` готов, вызова нет; формат `generated_files`.
- implement: писать `.p1/.p2/.p3` для каждого узла, учитывать в манифесте и проверке.
- verify: 50 узлов → до 150 файлов, проверка узлов не ломается.

### B2. Opera backoff
- investigate: 76 проверок подряд каждые ~40 с; endpoint'ы живы по TCP, протокол edge молчит.
- implement: экспоненциальная пауза 5→10→20 мин после серии неудач, лог раз в цикл.
- verify: число строк `[EU]` за 10 минут ≤ 5.

### B3. VLESS pre-flight TLS при импорте
- investigate: 26 из 40 узлов мертвы по TCP; у части сертификат не совпадает ни с SNI, ни с host.
- implement: один TLS-хендшейк на узел при импорте (таймаут 2 с, параллельно 8), отбраковка.
- verify: доля «ядовитых» узлов в группе → 0, время импорта не растёт более чем вдвое.
