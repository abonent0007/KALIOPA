## Активная маршрутизация

| Слот | Что | Выход |
|---|---|---|
| Основной VPN | Cloudflare MASQUE (`nova-go`, SOCKS5 1370) | RU |
| Дополнительный VPN | **Opera EU** (HTTP 1371, `opera-proxy`) | SE, `77.111.247.19` |
| Telegram | WARP-socks в релее 1372 | RU |
| Tor | выключен (1375/1378 закрыты) | — |

Правила PAC (сверху вниз): `user_direct → user_ru → user_eu → eu_over_exclude →
exclude → локальные TLD → DIRECT → режимы приложений → AI-домены → eu → youtube →
ru → discord → telegram → whatsapp → Cloudflare-IP → foreign-default (VPN)`.

Фактические маршруты из журнала:

- RU: `SOCKS5 127.0.0.1:1370; PROXY 127.0.0.1:1371` (основной первым);
- EU/YouTube: `PROXY 127.0.0.1:1371; SOCKS5 127.0.0.1:1370`;
- AI-приложения (`ai_apps=opera`): `PROXY 127.0.0.1:1371`;
- Telegram: WARP-socks; relay не использует `opera-http` для MTProto.

Настройки лежат в `%LOCALAPPDATA%\Nova\temp\routing_settings.json` (приоритетнее
корневого `routing_settings.json`):

```json
"secondary": {"mode": "opera"},
"opera_region": "EU",
"routes": {"ai_apps": "opera", "telegram": "warp", "browser": "auto", ...}
```

Правятся только при остановленной Nova: файл перезаписывается при выходе.

## Личность релея (1.44.2.15)

`API_RELAY_KEY_VERSION` больше не константа. Логин `nova-pc-<version>` собирается
из версии, под которую выпущен ключ:

- `resources/nova_relay_identity.py` читает ключ, берёт версии из релизов upstream
  (`version.json` + `releases.atom`), пробует их через WARP и кэширует ту, которую
  ключ реально принимает;
- кэш — `temp/relay_identity.json`, маркер — `profiles/opera_relay.version`;
- фоновая проверка идёт после старта и повторяется, пока WARP не поднимется;
- `NOVA_RELAY_KEY_VERSION` — ручной override.

Факт на 2026-11-01: публичный установщик upstream 1.44.2 содержит ключ, который
принимает логин **1.44.1**; `nova-pc-1.44.2` получает 407. Старый ключ 1.43.2
сохранён в `C:\lib\backup-nova\opera_relay.key.1.43.2`. В логе:
`[Relay] ключ принят для версии 1.44.1 (upstream: 1.44.2).`

## Убранные хардкоды и дублирование (1.44.2.14)

- `resources/nova_win_ps.py` — один запуск PowerShell вместо двух копий
  (`nova_dns_adapters`, `nova_process_hygiene`); там же единый разбор JSON и текст ошибки.
- `tools/install_overlay.ps1` — путь сборки `$env:USERPROFILE\Documents\build\Inno`,
  а не `C:\Users\User\...`.
- `tgrelay` — виды egress вынесены в `_MT_PROTO_BLOCKED_EGRESS` / `_PROFILE_EGRESS`.
- `nova_doh_service` — порт резолвера `NOVA_DOH_PORT` (по умолчанию 53).
- `nova.pyw` — таймаут выбора Opera-сервера `NOVA_OPERA_SELECTION_TIMEOUT` (10 с, 3–30).
- `nova_vless_preflight` — `NOVA_VLESS_PREFLIGHT_TIMEOUT` (2 с), `NOVA_VLESS_PREFLIGHT_WORKERS` (8).
- `nova_proton` — `NOVA_PROTON_VARIANT_COUNT` (3, границы 1–5) и устойчивый импорт без модуля вариантов.
- `nova_opera_feed` — `NOVA_OPERA_ENDPOINTS_URL` (свой источник раньше зеркал).
- `nova_process_hygiene` — `NOVA_PROCESS_ORPHAN_AGE` (600 с, минимум 60).

Намеренно оставлены как константы: версия relay-ключа `API_RELAY_KEY_VERSION=1.43.2`
(ключ выпущен под неё), порты 1369–1380, `DEFAULT_OPERA_FAKE_SNI=www.microsoft.com`.

## Известные ограничения

- **Opera US мёртв** (2026-11-01): discover отдаёт `.246.61`, он не отвечает; рабочий регион — EU.
- **Публичные VLESS-узлы** — 40 из 40 проверенных мертвы даже через настоящий
  `nova-xray` (`tools/vless_chatgpt_probe.py`); подписки остаются, карантин их отсеивает.
- **Proton WG** — handshake блокируется сетью провайдера; варианты портов не помогают.
- **D2 (свой VPS)** и **D3 (Flow Unlocker)** не реализованы: нужны внешний сервер и
  ручная загрузка расширения в Chrome.
- **E2 (точный фон)** — исходное фото не сохранилось; используется `img/background.png`.
- Если Opera умрёт целиком, ChatGPT перестанет открываться: PAC уйдёт на WARP, где
  OpenAI отдаёт 403. Приложение само переберёт endpoint'ы и уйдёт в backoff.
