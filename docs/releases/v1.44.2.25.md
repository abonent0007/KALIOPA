## Что нового

### WARP: порядок по реальному пингу, а не по имени

- `warp-generated-state.json` хранит `rtt_ms: 999`, пока скан не измерил хост.
  Из-за этого все свои профили были равны, и группа `AWG Cloudflare` шла по
  алфавиту: `WARPgen_01` первым, даже когда `WARPgen_09` пингует 28 мс.
- Теперь порядок берёт `rtt_ms` и `fail_streak` из `profile-stats.json`, а
  состояние генератора — только как резерв.
- Профиль, который уже вёз трафик (`ok >= 2`), идёт раньше непроверенного:
  низкий TCP-пинг не доказывает, что Cloudflare примет ключ. Например,
  `WARPgen_09` отвечает за 28 мс, но туннель не поднимает (`сбой`).
- Список `AWG Cloudflare` сортируется: живой → рабочие → непроверенные →
  сбои; внутри — по пингу. В заголовке — «рабочие → пинг».

### Живая проверка

- Проверены профили `WARPgen_01`, `02`, `04`, `09`, `10`, `12`, `13`, `14`,
  `15`: `04/09/10/13/14` не подняли туннель, `01/02` работают,
  `WARPgen_15` (`162.159.192.1:4500`) показал лучший результат — до ~8 Мбит/с.
- `WARPgen_15` оставлен выбранным; это явный профиль, а не группа, чтобы
  автоматика не вернулась на медленный узел.
