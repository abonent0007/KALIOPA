## Что нового

### DNS-AI теперь действительно разблокирует — по DoH

Выяснилось, почему разблокировка «не работала»: у **dns-ai.ru нет обычного
DNS по UDP/53**, сервис отвечает только по DoH и требует HTTP/2 (на HTTP/1.1
отдаёт 505). NRPT-правила Windows умеют указывать только IP-адрес, а встроенного
DoH-клиента на этой сборке Windows нет. В итоге UDP-замер видел подменённые
DPI ответы, не находил «разблокирующих» провайдеров и правила не ставились.

Добавлен собственный резолвер:

- `nova-go dns doh` — локальный DNS-слушатель на `127.0.0.1:53`, пересылает
  запросы в `https://dns.dns-ai.ru/dns-query` по HTTP/2 (Go), с кэшем на 60 с,
  UDP и TCP, и `SERVFAIL` при недоступном апстриме;
- апстрим идёт через живой слот Nova: сначала WARP SOCKS `127.0.0.1:1370`,
  затем HTTP Opera `127.0.0.1:1371`; напрямую DoH в РФ рвётся DPI;
- `resources/nova_dns_doh.py` — запуск/остановка резолвера, сравнение его
  ответов с системным DNS, кэш поддержки на сутки;
- NRPT-правила теперь указывают на `127.0.0.1` для имён, где DoH даёт другие
  адреса. Правила и резолвер живут вместе: при остановке резолвера правила
  снимаются, при падении Nova helper выходит по `--parent-pid`;
- если на старте туннель ещё не поднят, подписка повторяет настройку, когда
  появится SOCKS-порт (до 2 минут), вместо «правил нет до перезапуска».

**Замер:** `gemini.google.com` через DoH → `89.169.55.148` (прокси dns-ai),
сервис отвечает 200 через WARP; `chatgpt.com` → `62.60.230.61`, но ChatGPT
по-прежнему требует Opera EU (403 через WARP — это ограничение Cloudflare,
не DNS-AI). Правило с `127.0.0.1` проверено вручную: Windows резолвит имя через
локальный резолвер и получает адрес dns-ai.
