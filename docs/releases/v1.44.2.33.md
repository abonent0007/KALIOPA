## Что нового

### Стабильность после 1.44.2.31–1.44.2.32

Разбор поломки: основной слот был переключён на **MASQUE**, а он на этой сети
не тянет YouTube (замер: `youtube.com` через 1370 — таймаут 17.7 с; через
WARP-профиль — 200 за 2.6 с). Плюс 1.44.2.32 на старте пытался поднять
DoH-резолвер до подключения туннеля: 12 секунд ожидания и ошибка в журнале.

Исправлено:

- основной слот возвращён на **Custom/WARPgen_custom_07** (WARP, проверен);
- DoH-резолвер DNS-AI **не запускается, пока закрыт слот**: настройка
  откладывается и повторяется один раз, когда туннель поднялся (без задержки
  старта и без ошибок в журнале);
- если `127.0.0.1:53` занят другим резолвером, DNS-AI садится на
  **`127.0.0.2:53`** и правила указывают туда — «свой адрес» вместо общего
  порта (NRPT не умеет порт, только IP);
- правила и резолвер по-прежнему живут вместе: нет резолвера — правила сняты.

### DNS-AI по DoH (вошло в эту сборку из 1.44.2.32)

- `nova-go dns doh` — локальный DNS-резолвер, пересылает запросы в
  `https://dns.dns-ai.ru/dns-query` по HTTP/2 (UDP/53 у сервиса нет, HTTP/1.1
  он отвергает). Апстрим идёт через живой слот Nova, напрямую DoH рвётся DPI.
- Резолвер поднимается только после подключения и останавливается вместе с
  правилами; кэш поддержки — сутки.
- Если `127.0.0.1:53` занят, используется `127.0.0.2:53`.
